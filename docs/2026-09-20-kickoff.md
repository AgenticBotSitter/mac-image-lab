# Mac Image Lab — Kickoff

**Date:** 2026-09-20
**Status:** planning complete; implementation not started

## Declaration

Mac Image Lab is a Marvin-owned, local-only image generation control plane for the M4 Pro Mac mini. Its canonical local and R2 homes are:

- Local: `~/hermes-data/Marvin/Mac Image Lab/`
- R2: `hermes-data/Marvin/Mac Image Lab/`

The user explicitly selected this R2 location.

## Why this exists

The Mac already runs Qwen-Image-2.1 successfully through local ComfyUI/MPS. The lab will make that capability easier to operate and reproduce without exposing ComfyUI’s graph editor or opening a public service.

## Technical decision

Use a small loopback-only Gradio UI that talks to local ComfyUI at `127.0.0.1:8188` through its HTTP API.

Do not port `joeynyc/spark-image-lab` directly. That project is an NVIDIA CUDA/DGX Spark application: it hard-requires CUDA, uses a NVIDIA PyTorch container, and is not supported on macOS. Its UX pattern—simple controls, history, receipts, and result reuse—is the reference, not its runtime.

## Current constraints

- Qwen-Image-2.1 work is research/evaluation only.
- No public hosting, model sharing, social posting, store listing, paid API call, or cron change is in scope.
- R2 is the canonical retained-artifact store; every archive requires exact-key `head_object` verification.
- MPS maximum-native Qwen renders are slow and must remain an intentional profile, not the default.
